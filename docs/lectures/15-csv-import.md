# Лекція 15. Імпорт даних: CSV → SQLite

*Досі кожен рядок таблиці потрапляв у базу через власноруч написаний
`INSERT`. Але на практиці дані частіше приходять готовим файлом
(вивантаженням з Excel, вебсервісу чи іншої системи) у форматі CSV
("comma-separated values", значення через кому). Переписувати сотні
рядків такого файлу в `INSERT` вручну не варіант. SQLite вміє
завантажити CSV напряму, але тут є пастка, пов'язана з первинним
ключем `id`, яку ця лекція розбирає детально.*

## 1. CSV: простий текстовий формат таблиці

```text
title,author,publication_year,genre,copies_count
Проза,Автор Х,2000,роман,2
Друга книга,Автор Y,2001,повість,1
```

Перший рядок CSV-файлу містить заголовки колонок, а кожен наступний рядок
містить одне значення таблиці, розділене комами. Це найпоширеніший формат
обміну табличними даними між зовсім різними програмами (Excel, Google
Таблиці, експорт з будь-якої СУБД).

## 2. Базовий імпорт: .mode csv і .import (CLI)

```text
.mode csv
.import --skip 1 new_books.csv books_staging
```

У CLI `sqlite3` дот-команда `.mode csv` перемикає режим введення на
CSV, а `.import файл.csv таблиця` завантажує кожен рядок файлу як
рядок вказаної таблиці. Прапорець `--skip 1` пропускає перший рядок
(заголовки), щоб він не потрапив у таблицю як звичайні дані.

## 3. Пастка: CSV без id, а в таблиці id є

Пряма спроба `.import new_books.csv books` (де `books` є вже наявна
таблиця-вимір з колонкою `id INTEGER PRIMARY KEY`) майже завжди йде не
так: CSV має **5** колонок (`title, author, publication_year, genre,
copies_count`), а таблиця `books` має **6** (додається `id`). Кількість
колонок CSV повинна точно відповідати кількості колонок цільової
таблиці; інакше `.import` або відмовляється працювати, або (що
гірше) розставляє значення по колонках неправильно.

## 4. Рішення: проміжна (staging) таблиця

```sql
-- 1. Проміжна таблиця з РІВНО тими колонками, що в CSV (без id)
CREATE TABLE books_staging (
    title TEXT,
    author TEXT,
    publication_year INTEGER,
    genre TEXT,
    copies_count INTEGER
);
```

```text
-- 2. Імпорт CSV саме в неї — кількість колонок збігається
.mode csv
.import --skip 1 new_books.csv books_staging
```

```sql
-- 3. Перенесення в реальну таблицю: id SQLite призначає сам
INSERT INTO books (title, author, publication_year, genre, copies_count)
SELECT title, author, publication_year, genre, copies_count
FROM books_staging;

-- 4. Проміжна таблиця більше не потрібна
DROP TABLE books_staging;
```

Після `INSERT ... SELECT` нові рядки отримують
свої `id`, що природно продовжують нумерацію вже наявних рядків
таблиці (наприклад, якщо в `books` уже було 2 рядки з `id = 1, 2`, нові
рядки з `books_staging` отримують `id = 3, 4`: SQLite сам призначає
значення для `INTEGER PRIMARY KEY`, коли колонку не вказано в
`INSERT`). Сама проміжна таблиця (`books_staging`) є тимчасовим
"контейнером" лише для перенесення даних; `DROP TABLE` після переносу
прибирає її, не торкаючись основної таблиці й уже перенесених даних.

## 5. Той самий принцип у DB Browser for SQLite

DB Browser for SQLite має власний майстер імпорту
(**File → Import → Table from CSV**), який теж створює нову таблицю
безпосередньо з колонок CSV-файлу. Якщо потрібно додати рядки в УЖЕ
наявну таблицю з колонкою `id`, принцип той самий: спершу імпортувати
CSV як нову (проміжну) таблицю через майстер, а потім виконати той
самий `INSERT ... SELECT` у вкладці **Execute SQL**, як і в CLI.

## 6. Перевірка результату

```sql
SELECT COUNT(*) FROM books;
```

Найпростіше підтвердити, що імпорт спрацював, порівнявши
кількість рядків (`COUNT(*)`, Лекція 8) ДО і ПІСЛЯ імпорту: різниця
має дорівнювати кількості рядків у CSV-файлі (без рядка заголовків).

## 7. Розбір на прикладі: що саме потрапляє в таблицю

Візьмемо файл `new_books.csv` із трьома книгами. У першій книзі автор записаний із комою всередині («Коцюбинський, Михайло»), тому значення взято в лапки, а в другій не вказано кількість примірників:

```text
title,author,publication_year,genre,copies_count
Тіні забутих предків,"Коцюбинський, Михайло",1911,повість,3
Захар Беркут,Іван Франко,1883,роман,
"Лісова пісня",Леся Українка,1911,драма,2
```

Імпортуємо його в проміжну таблицю `books_staging` так, як описано в розділі 4, і подивимось на результат:

```sql
SELECT title, author, copies_count, typeof(copies_count) AS kind
FROM books_staging;
```

```text
title                 author                 copies_count  kind
Тіні забутих предків  Коцюбинський, Михайло  3             integer
Захар Беркут          Іван Франко                          text
Лісова пісня          Леся Українка          2             integer
```

Лапки спрацювали правильно: `Коцюбинський, Михайло` залишилось одним значенням, а не розпалось на дві колонки. Якщо в значенні є кома, його обов'язково беруть у лапки; без потреби лапки теж допустимі, як навколо «Лісова пісня» в третьому рядку, і на результат не впливають. Порожнє поле в другому рядку потрапило в таблицю не як `NULL`, а як **порожній рядок** (тип `text`). Для бази це різні речі: `COUNT(copies_count)` порахує такий рядок, а `AVG` врахує його як нуль: замість (3 + 2) / 2 = 2.5 вийде (3 + 0 + 2) / 3 ≈ 1.67. Тому під час перенесення в реальну таблицю порожні рядки варто перетворити на `NULL` функцією `NULLIF`:

```sql
INSERT INTO books (title, author, publication_year, genre, copies_count)
SELECT title, author, publication_year, genre, NULLIF(copies_count, '')
FROM books_staging;
```

`NULLIF(a, b)` повертає `NULL`, якщо `a` дорівнює `b`, і `a` в іншому разі. Після такого перенесення в колонці `copies_count` у «Захара Беркута» стоїть справжній `NULL`.

## 8. Типові проблеми імпорту

**Кількість колонок не збігається.** Якщо спробувати імпортувати цей самий файл безпосередньо в `books` (шість колонок, перша з них `id`), SQLite повідомить про помилку для кожного рядка:

```text
new_books.csv:2: expected 6 columns but found 5 - filling the rest with NULL
new_books.csv:2: INSERT failed: datatype mismatch
```

Назва книги намагається потрапити в колонку `id`, яка приймає лише цілі числа, і рядок відхиляється. У таблиці не з'явилось жодного нового рядка. Проміжна таблиця з розділу 4 і була придумана, щоб цього уникнути.

**Заголовок потрапив у дані.** Без `--skip 1` перший рядок файлу не пропускається, і імпорт у вже наявну таблицю додасть заголовки як звичайний рядок. Якщо імпортувати файл із трьома книгами в порожню таблицю без `--skip 1`, у ній опиниться чотири рядки, а в колонці `publication_year` першого з них буде текст `publication_year`. Наслідок помітний не одразу: помилки не буде, зате `MAX(publication_year)` поверне не рік, а цей текст, бо в SQLite текст вважається «більшим» за будь-яке число.

**Інший роздільник.** Excel із українськими регіональними налаштуваннями зазвичай розділяє значення крапкою з комою, бо кома в таких налаштуваннях використовується як десятковий знак. Рядок `Кобзар;Тарас Шевченко;1840;поезія;5` при імпорті за умовчанням стає одним довгим значенням у першій колонці. Роздільник змінюється командою перед імпортом:

```text
.mode csv
.separator ;
.import --skip 1 books_semicolon.csv books_staging
```

**Кодування.** SQLite очікує файл у UTF-8. Якщо файл збережено в старому кодуванні Windows-1251, кирилиця перетвориться на нечитабельні знаки. У Excel у такому випадку обирайте формат **CSV UTF-8** замість звичайного «CSV».

**Типи.** Якщо імпортувати файл у таблицю, якої ще не існує, SQLite створить її сам: назви колонок візьме з першого рядка файлу, а тип кожної колонки призначить `TEXT`.

```text
.import new_books.csv fresh
.schema fresh
```

```text
CREATE TABLE IF NOT EXISTS "fresh"("title" TEXT, "author" TEXT, "publication_year" TEXT,
 "genre" TEXT, "copies_count" TEXT);
```

Тож роки й кількості опиняться текстовими. Це ще одна причина користуватись проміжною таблицею: її ви створюєте самі, з потрібними типами, або перетворюєте значення під час `INSERT ... SELECT` через `CAST(publication_year AS INTEGER)`.

**Повторне перенесення.** Якщо виконати `INSERT ... SELECT` двічі, кожна книга з'явиться в `books` двічі: SQLite не перевіряє, чи такі рядки вже є. Тому порівнюйте `COUNT(*)` до й після (розділ 6), а проміжну таблицю одразу після перенесення видаляйте, щоб випадково не перенести її вдруге.

## 9. Експорт: із таблиці назад у CSV

Зворотна операція виконується тими самими дот-командами:

```text
.headers on
.mode csv
.output books_export.csv
SELECT title, author FROM books;
.output stdout
```

`.headers on` додає рядок заголовків, `.output файл` перенаправляє результат запиту у файл замість екрана, а `.output stdout` повертає виведення на екран. У файл потрапляє результат **будь-якого** `SELECT`, тож експортувати можна не лише всю таблицю, а й відфільтровану вибірку чи підсумковий звіт. Значення, що містять кому, SQLite бере в лапки автоматично.

## 10. Запитання для самоперевірки

**Чому не можна просто виконати `.import new_books.csv books`, якщо в `books` є колонка `id`?**

Кількість колонок у файлі (5) не збігається з кількістю колонок таблиці (6), тому значення зсуваються або рядки відхиляються з помилкою `datatype mismatch`. Правильний шлях: імпортувати у проміжну таблицю й перенести дані через `INSERT ... SELECT`.

**Що означає прапорець `--skip 1`?**

Пропустити перший рядок файлу, тобто рядок заголовків, щоб він не став звичайним рядком даних.

**У CSV порожнє значення. Чим воно стане в таблиці після `.import`?**

Порожнім рядком (`''`), а не `NULL`. Щоб отримати `NULL`, застосуйте `NULLIF(колонка, '')` під час перенесення.

**Файл відкрився в Excel нормально, але після `.import` усі п'ять колонок злилися в одну. У чому причина?**

Файл використовує крапку з комою як роздільник, а SQLite очікує кому. Перед імпортом потрібна команда `.separator ;`.

**Як перевірити, що імпорт завершився повністю?**

Порівняти `COUNT(*)` до й після імпорту: різниця має дорівнювати кількості рядків файлу без рядка заголовків.

## Підсумок

- CSV є текстовим форматом таблиці: перший рядок містить заголовки колонок,
  далі йдуть значення через кому, один рядок файлу = один рядок таблиці.
- `.mode csv` + `.import --skip 1 файл.csv таблиця`: базовий імпорт у
  CLI `sqlite3`; кількість колонок CSV має точно відповідати кількості
  колонок цільової таблиці.
- Якщо цільова таблиця має колонку `id INTEGER PRIMARY KEY`, якої в
  CSV немає, пряме `.import` в неї не спрацює; розв'язок: імпорт у
  проміжну таблицю з колонками CSV, а потім `INSERT ... SELECT` у
  реальну таблицю (SQLite сам призначить нові `id`), і `DROP TABLE`
  проміжної.
- `COUNT(*)` до й після імпорту: простий спосіб підтвердити, що всі
  рядки файлу дійсно потрапили в таблицю.
- Порожнє поле CSV потрапляє в таблицю порожнім рядком, а не `NULL`; виправляється `NULLIF(колонка, '')` під час `INSERT ... SELECT`.
- Для файлів із крапкою з комою потрібна команда `.separator ;`, а кирилиця має бути в кодуванні UTF-8.
